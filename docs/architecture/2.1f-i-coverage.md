### 2.1f-i Coverage — `universe_builder status --coverage`

`status` counts atoms on disk, which says nothing about whether a civilisation is
*finished*: a topic that was never generated looks exactly like one that does not
exist. Coverage compares the topics the stored History atoms list against what is
on disk, per civilisation and atom type.

It rests on `store.atoms_for()`, which globs on the content id and so finds a
topic's atom whichever model wrote it. **That is only possible because the corpus
is content-addressed** — before the migration there was no way to ask the
question without already knowing which model had answered it.

Three states, not two. "Attempted and failed" (an `_ERROR` sentinel) is reported
separately from "never generated", because one needs a fix pass and the other a
create pass. An `EmptyModel` placeholder counts as *not* covered: it is a file,
but reporting a civilisation complete when part of it is `{"error": "No data
found"}` would be a lie. `--gaps` names the missing topics, and the command exits
non-zero while anything is outstanding so a script can gate on it.
