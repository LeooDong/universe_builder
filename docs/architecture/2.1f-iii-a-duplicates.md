### 2.1f-iii-a Duplicate atoms — `src/universe_builder/duplicates.py`, `universe_builder duplicates`

**Two atoms for one subject pass every invariant the project has.**
`tests/test_corpus.py` asserts that no two files share a content id, and
duplicates do not: the ids were hashed from the two *spellings* two models
happened to use. `Founding of Memphis` (gpt-4o-mini) and `Foundation of
Memphis` (gpt-5-nano) were one event in two files — Egyptian History keeps one
atom per model by design, the two models spelled the topic differently, and
`group_synonyms` joins only names that *declare* equivalence or that the alias
file joins by hand. The newer atom listed `Founding of Memphis` in its own
`otherNames`, so the corpus declared the equivalence outright and nothing read
it; `stored_name_claims` is what reads it now.

`universe_builder duplicates` is dry by default, like `periods`. The keep
rule is **the later model family wins** — `gpt-5-nano` outranks `gpt-4o-mini`.
A tie within one family is *not* resolved: nothing in a filename ranks two
same-generation atoms, so the pair is reported `UNDECIDED` for a human.
`--except TEXT` drops a pair outright, because **a shared name is evidence of a
duplicate, not proof of one** — the modern Bibliotheca Alexandrina names the
ancient Great Library of Alexandria as a related work, not as an alias.

`plan()` reads its inputs once (the distinct and alias files, the per-type
owners, each type's `listed_spellings`) and hands every component to
`_decide_component`, which returns a `Resolution`, an `Undecided` or a
`Skipped` (v0.2.0): ruled out first, then a `--keep`
survivor (`_named_survivor_decision`), else the model-family rank with the
gated fill tie-break (`_ranked_decision`). `Plan.undecided` and
`Plan.skipped` still hold dicts (`as_dict()`), the shape reports read.
`_trim_covered`, `_stars_only` and `_without_alias_chains` then run over the
whole plan, as before.

**Retiring the file is only half the repair**, and the other half is the half
that is easy to forget: the losing spelling is still listed in a stored History
atom, so removing only the file leaves `topics.needing_create` seeing a listed
topic with no atom, and the next create run regenerates the duplicate and bills
for it. So an alias line is written first, and three things about it are
load-bearing:

- **It speaks in listed spellings, not the atoms' `name.common`.** An atom
  generated for `Shaduf (irrigation tool)` can call itself simply `Shaduf`; a
  line in common names alone joins two names nothing lists.
- **One line per survivor, not per pair.** An atom can beat several rivals, and
  a line each puts two same-scope declarations in the file both claiming the
  survivor's name — which `group_occurrences` treats as ambiguous and leaves
  ungrouped, so the lines written to join the spellings would stop the work list
  joining them.
- **A line that would claim a name another atom type lists is refused.** The
  alias file has no per-type scope and `alias_keys` splits a trailing
  parenthetical, so a line reading `… by King Menes (Narmer)` claims the bare
  key `narmer` and costs the *people* their Narmer topic. Observed on the real
  corpus: the first run did exactly that.

**Alias lines merge with what the file already holds.** Appending blindly is
wrong *across runs*: a later `--apply` that retires another rival of an
already-processed survivor writes a second line starting with the same name, and
two same-scope declarations claiming one key is the ambiguity case — every
matching entry is left ungrouped, so a topic that resolved yesterday drops out
of the work list today. `Ottoman conquest of Egypt` failed exactly this way on
the second run and `Conquest of Egypt by the Ottoman Empire` vanished from
coverage. Merging only touches *global* lines; a scoped one is a deliberately
narrower claim and is never widened.

**And merging itself never chains.** This is the third and outermost place the
Saqqara rule has to hold — `_stars_only` covers retirements, `alias_lines`
covers two rivals of one survivor within a plan, and this covers the file. A
line that overlaps *two* existing declarations would join everything they hold
(`A = B` plus `C = D` plus a new `B = C` becomes `A = B = C = D`, and nothing
declared `A = D`), and *two* new lines touching one existing line chain through
it, because the first write is what the second sees. Both are refused at plan
time, so the pair is reported `UNDECIDED` and **not retired** — the line is the
half of the repair that stops regeneration, so a retirement without it is
unsafe. The writer raises as a backstop, before any file moves.

**Every one of these checks folds names through `topics.alias_keys`, not
`topics.name_key`**, and the difference is the whole safeguard. `alias_keys` splits
a trailing parenthetical (`Foo (Bar)` declares `foo bar`, `foo` *and* `bar`),
which is what `group_occurrences` sees; `name_key` returns only the whole string.
Comparing with `name_key` made every overlap check blind to the split, so a file
holding `Foo (Bar) = Qux` looked like it claimed `{foo bar, qux}` and a new
`Bar = Baz` line showed no overlap at all — it was appended, two declarations
then claimed `bar`, and the retired spelling stopped resolving. If the two
foldings ever diverge again, a name can be claimed twice with no check noticing;
a test pins them equal.

**`not_duplicates.txt` is the mirror of `aliases.txt`**, and the reason it
exists is that the shared-name signal is wrong about half the time on real data.
`aliases.txt` says "these spellings are one topic"; this says "these atoms are
different things, whatever their names suggest" — two pharaohs sharing a
prenomen (`Wahibre`), two Cairo gates sharing an epithet (`Gate of Victory`),
Nicaea and Nice sharing a Greek root. Format is `A != B`. Without a durable
declaration every run resurfaces the same false positives until someone merges
Nice into Nicaea.

**`--keep TEXT` names the survivor** for a pair the model-family rule cannot
rank, by a substring of its filename (a content id is the unambiguous choice).
It answers *which atom survives* and nothing else: the cross-atom-type alias
check still applies, because a human naming a survivor has not reviewed the line
that will be written.

Both halves are reversible. The alias file is in git; the retired atom moves to
`_duplicates/` rather than being unlinked, because `data/` is not in git and
there is no undo.

Two refusals follow from the same reasoning:

- **A pack with no alias file cannot retire at all.** There would be nowhere to
  record the surviving spelling, so `needing_create` would regenerate what was
  just retired and bill for it. `apply` raises rather than doing half the repair.
- **Only a star is applied.** Duplicate pairs are edges in a graph, and
  **pairwise equivalence does not compose** — the Saqqara rule again. Exactly
  one shape is safe: a component where a single atom is never retired and every
  other is retired in its favour. `Amarna Boundary Stelae` beating two rivals is
  that shape, and collapses to one alias line naming one survivor.

  Two shapes are not, and both look locally sensible while destroying data.
  A **chain** (`Alpha`-`Beta`, `Beta`-`Gamma`) makes Beta win one pair and lose
  the other, so applying both retires Beta while an alias line still names it
  Alpha's survivor and the file declares `Alpha -> Beta -> Gamma`. **Two
  survivors claiming one loser** (`Alpha`-`Beta`, `Gamma`-`Beta`) is the case a
  keeper-vs-retiree check cannot see, because no keeper is ever retired: it
  destroys the only atom linking Alpha and Gamma, keeps both, and writes two
  same-scope lines each claiming Beta's name — which `group_occurrences` reads
  as ambiguous, so Beta's listed spelling resolves to nothing and the next
  create run regenerates the atom just retired.

  In both, "which atom survives" is exactly what the component fails to answer,
  so every resolution in it moves to `UNDECIDED` — including any that looks
  fine alone.
