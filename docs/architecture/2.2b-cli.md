### 2.2b Pipeline config and CLI, continued — `cli.py`

A wrapper installed under another name (a pack that installs this engine) calls
`cli.main(argv, prog=...)`, and `run_batch.main` takes the same `prog=`. The
name reaches the usage line and every hand-written "now run this" hint
(`cli._prog(args)`); the hints once still said `universe_builder`,
a different command under a wrapper. The batch-collect hint names
`python -m <prog>.run_batch` (`cli._batch_prog`): a wrapper ships
its own `<prog>.run_batch`, which loads its `.env` and pack
where the engine's module would load neither. The provenance headers written
into alias files are not rewritten: `topics` recognises them by text.

`cli.py` parses, prints and dispatches; what a verb decides lives in its
module (v0.2.0): `lint.identity_decider` builds the
`--review --via SOURCE` verdicts, `sources.run` is the propose/verify/append
loop (returning a `sources.Report`; the CLI prints through its callbacks),
`duplicates.triage_scope`/`verdict_counts`/`save_verdicts` are the triage's
bookkeeping, and `collisions.load_seed` finds the seed `--seed NAME` names.
Old phase names have one table, `pipeline.LEGACY_PHASES`, read through
`pipeline.modern_phase` by the CLI, `work.select_work`, `execute_prompt` and
`costs` (`cli.LEGACY_PHASES` is the same object).

The `universe_builder` command has six subcommands:

| Command | Does |
|---|---|
| `universe_builder run --phase <p> [--atom <a>] [--model <m>] [--effort <e>] [--task-budget N] [--provider <P>] [--limit N] [--batch] [--dry-run]` | Runs exactly one phase. The `run_*` functions bundle two or three phases together, which is why there was previously no way to fix without also verifying. `--limit N` is **per atom type, and 0 is nothing**, on every path (dry run, sync, batch, `run_batch submit`); a negative limit is refused. `--batch` opens no journal run (the handle in `_batches/` is the submission's record; `collect` journals). |
| `universe_builder config` | Prints the resolved configuration with provenance. |
| `universe_builder status [--coverage] [--gaps]` | Counts stored atoms and outstanding `_ERROR` files per atom type; `--coverage`/`--gaps` report what is missing. |
| `universe_builder index` | Rebuilds the derived cross-reference index (`links.json`). |
| `universe_builder collisions --seed NAME [--review F] [--via model]` | Names an incoming index seed (a History atom, for history) shares with the stored corpus, run **after `--phase index` and before `--phase create`** (`--history NAME` is the older spelling of the flag and still works) — the seed is the only thing that can name the collisions, and `aliases.txt` is read by `topics` when it builds the create work list, not by the generation path, so that window is the real constraint. Overlap is free (a re-pinned topic costs nothing); *re-spelling* is not, because the content id hashes the topic string and `Massalia (Marseille)` and `Massilia (Marseille)` are one city with two ids. **Detection is mechanical and deliberately noisy; adjudication is not.** Recall is what detection needs — a missed pair ships a duplicate — while a verdict needs precision, since asserting wrongly merges two subjects, which is worse. On the Roman seed the mechanical signal alone got most candidates wrong (`Cannae`/`Carrhae`, `Pantheon`/`Parthenon`, `Justin I`/`Justinian I`). `--via model` judges each pair on the frontier tier and got every one right, refusing all the noise and abstaining on `Narses`/`Narseh` — a Byzantine general against a Sasanian shah — rather than guessing. Output is `universe_builder lint`'s review format, so the alias writing, the dry run and the typo'd-verdict refusal are reused rather than rebuilt; `wrong` is offered only for a candidate a stored atom actually claims, since it deletes. It also lists every **re-pin** (a topic whose id is already stored) with the other Histories that name it (`collisions.shared`): a re-pin is usually one subject, and it is also where one bare name meaning two things hides, which no candidate row can show. A History's civilisation name is recovered from its content id against the seed list (`topics._context_of`), not from the slug, which drops hyphens and accents; `--seed` matches by id the same way. Stored ids are read with `decompose_filename` (never `split("_")[1]`, wrong for an underscored atom type), and the stored index is a list, not keyed on the folded slug, so atoms sharing a slug — every CJK subject slugs to the empty string — each keep their claims and similar matches (v0.1.20). |
| `universe_builder costs [--by K] [--atom A] [--run ID] [--since ISO] [--json]` | What each run, atom, model or subject actually cost, aggregated out of the journal. **Stores nothing** — like `universe_builder index` it is derived and always recomputable, and a full scan of a corpus's journal takes a fraction of a second, so there is no ledger to keep in step with the record it summarises. Its whole difficulty is provenance, and the report never collapses the three states: a cost the journal *reported*, one *recomputed* here from stored tokens against today's prices (much of an older corpus, because the field postdates it), and an attempt that is *unpriceable* because no usage was recorded. The last is the dangerous one — averaged in at zero it makes a model look cheaper — so it is excluded from every figure and named in a footer. A mechanical write (`journal.is_mechanical`: a pack's list verb, a relabel) is not an attempt at all here: it is in no row, no total and no footer but its own count. `--by subject` is the finest grain: one row per atom generated, which is where the true cost of a defect shows up (a repaired atom's cost spans both calls — the nano original and the frontier repair). `--by effort` (v0.6.0) is model and the effort it sent together (`gpt-6-luna @ low`; `@ default` for a line that sent none: every line before v0.6.0, and one whose model ignores effort). |
| `--provider openai-responses` / `openai-search` | Opt-in `/v1/responses` transport, the second with the `web_search` tool. Synchronous only — **`--batch` is refused**, because the batch submit and collect paths both speak Chat Completions. |
| `universe_builder sources [--atom A] [--limit N] [--only IDS_FILE] [--apply]` | Appends verified, resolvable source URLs to `name.sources`. **Additive** — nothing is removed — and every URL is fetched before it is written, because a model asked for citations produces plausible URLs whether or not it visited them. Resolves by default through the active pack's first free resolver — for history, **Wikipedia's own API** (`domains/history/wikipedia.py`, declared in `DomainPack.url_resolvers`): free, no key, no model — because the paid web-search tool was doing a title lookup: every URL it added was a Wikipedia article, at $10/1k calls plus input tokens each. `--via search` (core, always offered, never a default since it is paid) goes through `providers.run.complete` on the `openai-search` provider with a `SourceList` schema, takes a tier name for `--model` resolved against that provider's table (default `economy`), and journals every call into a `sources` run so `costs` sees the spend (v0.1.20; it used to call the SDK directly and record nothing). It keeps the model path for the cases where judgement beats recall (it returned `Alexander_the_Great#Egypt` where the API returns `Wars_of_Alexander_the_Great`). `--missing` restricts the pass to atoms citing no URL at all, which is the residue the free path cannot reach and the only place the paid path is worth its cost. Dry-run by default. The hosts it prefers (`DomainPack.preferred_hosts`) and the fields it reads country/state from to disambiguate a bare name (`DomainPack.coordinate_paths`) are the pack's, not core's. **A rejected URL is never offered again** (v0.4.0): `DomainPack.rejected_sources_path` names a TSV (`atom url reason date origin`, `atom` a `kind:hID`, `#` comments) that `sources.load_rejected` reads once per run into `{atom: {canonical_url}}`; `propose` drops an offered URL found there for *that* atom before anything fetches it (`Proposal.rejected_before`, counted in `Report.rejected_before` and printed), `apply` re-checks (reading the pack's file itself when not handed the map), and the comparison is `canonical_url`, so a `%28…%29` reject refuses the `(…)` spelling. No path or no file is no rejects; a malformed line stops the command (exit 2) rather than being skipped. `--only IDS_FILE` (one `kind:hID` per line; `sources.load_only`) restricts prefetch, propose and apply to those atoms, and names any key that matched no stored atom. |
| `universe_builder lint [--check C] [--atom A]` | Mechanical corpus checks — no model, no network, no writes. `overbroad-alias`: an atom claiming a name another atom calls itself, which makes that name ambiguous for everybody. `era-contradiction`: a structured `era` the surrounding prose disagrees with. `self-negation`: an atom whose own summarising prose (top-level `*summary*`/`significance`/`overview`/`abstract` fields) says its subject did not happen, does not exist, is fictional or hypothetical — "hypothetical" about a reconstruction excepted — marked strong when one of the pack's `date_paths` carries certainty `none`; on the history corpus it found nothing among live atoms and only genuine cases among retired ones. Exits non-zero on findings, 2 on an unknown check or atom name, and never reports clean when a check failed to run — a linter that says "no findings" after checking nothing is worse than one that errors. Repairs nothing by default; these are judgement calls. `--review FILE` writes them for adjudication, `--apply-review FILE --apply` acts: **same** adds an `aliases.txt` line and deletes nothing, **wrong** strips the false alias from that atom, and an atom that would not validate after the edit is left untouched. |
| `universe_builder duplicates --via model [--out F]` | Triages the UNDECIDED pile: is this component one subject at all? `group_synonyms` joins on declared names, and a name is evidence rather than proof — Roman emperors adopted predecessors' names by design, so `Marcus Aurelius`, `Caracalla` and `Elagabalus` all declare `Marcus Aurelius Antoninus` **correctly** and were grouped as one man. **The judge sees what each atom says about itself** (v0.4.0, `duplicates.triage_prompt`): its `name.common` and `otherNames`, year and era at each of the pack's `date_paths`, the named parts of the place at each `coordinate_paths` entry, ~300 characters of prose from the pack's `summary_paths` (`DomainPack.summary_paths`, type → dotted paths to a string, first non-empty wins; none declared, no summary; validated at registration), and `lint.corroboration`'s line when the pair has a comparable place or date. The system prompt says a subject that contains the other, or is a part, member, instance or copy of it, is a different subject. Reuses `collisions.Judgement`; writes only negatives, as `!=` lines in `not_duplicates.txt`, because declaring two atoms distinct quiets a report while retiring one destroys content. A component every pair of which differs is written as one multi-way line — `_declared_distinct` needs a single claim covering the whole component, so pairwise lines suppress nothing. Refuses any line contradicting a *global* `aliases.txt` line, compared through `alias_keys` as grouping folds (a scoped identity speaks only inside its civilisation, so it refuses nothing global); skips a claim an existing `!=` line already covers, every line split on every `!=` (v0.1.20). |
| **Identity has provenance** | `AliasGroup.provenance` is `asserted` (a person, or `collisions --via model` with the option to abstain) or `derived` (a pass recording its own conclusion so the retired spelling does not regenerate). Grouping honours both — the work list must follow the line whoever wrote it — but **safeguards accept only `asserted`**. Added after review found `duplicates._declared_same` reading lines `universe_builder duplicates --apply` had written as proof of identity, so the command cited itself to license its next retirement. Parsed from the header comments already on disk; `_merge_into_alias_file` takes its header from the caller so each writer records what it actually is. |
| `universe_builder retire --model TEXT [--apply]` | Retires the atoms an older model wrote to `_retired/`, leaving each topic with no atom so the next create run regenerates it. Never retires the index atom (dry-run by default). |
| `universe_builder restore --attempt ID [--run RUN] [--dry-run \| --apply]` | Writes back the bytes one journal attempt's in-place rewrite replaced (§2.1e), through `store.write_bytes`, journaling the restore as a mechanical `restore` line that keeps what *it* replaced — restoring that line's attempt undoes it. Dry by default (exit 1 while there is work); exit 1 when the attempt saved nothing, 2 when it is unknown, its copy fails its hash or is gone, or its target is outside the data dir (`restore.py`). |
| `universe_builder duplicates [--apply] [--keep TEXT] [--except TEXT]` | Atoms that declare a shared name — one subject, two files. Keeps the later model's atom, retires the other to `_duplicates/`, writes an alias line so the retired spelling is not regenerated (dry-run by default). Exits 1 while a resolvable pair is unapplied or an undecided one remains, and 0 when only declared-distinct or excluded pairs are left (those once exited 1 too, so the gate never passed). |
| `universe_builder periods [--apply-labels] [--split]` | Lints, adjudicates and splits city periods (history pack's `periods` op). |

**Why there is no second source API.** The obvious next move when Wikipedia
leaves a residue is another resolver behind it — Wikidata, Pleiades, the Met —
and it was measured rather than assumed. Nearly every sampled unsourced atom had
*some* Wikipedia search hit, so the residue is not a coverage gap: the articles
exist and the matcher declines them. Some of those hits were right
(`Cypriot coup of 1974` → `1974 Cypriot coup d'état`) and others were wrong, some
dangerously so (`Gothic invasion of Greece` → `German invasion of Greece`;
`Mummy of Artemidorus` → `British Museum`).

Both relaxations fail. Requiring the result's tokens to be a **subset** of the
subject's — today's rule — rejects the good half, since a correct article title
routinely adds a qualifier. Requiring a **superset** accepts the good half and
also reinstates `Memphis` → `Memphis, Tennessee`, the bug the rule exists to
prevent. Nothing distinguishes an added qualifier (`(1250)`) from an added
subject (`, Tennessee`) without knowing the topic.

So the missing ingredient is adjudication, not another index, and a further API
would inherit the same matcher and the same residue. That judgement is what the
paid model supplies: on the five hardest sampled cases it was right five times,
including the two the free path got actively wrong. Hence `--missing --via
search` rather than a resolver chain.
