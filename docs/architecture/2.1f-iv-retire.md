### 2.1f-iv Superseded atoms — `src/universe_builder/retire.py`, `universe_builder retire`

Once a later model produces materially better atoms, the old ones are not
duplicates to adjudicate: there is exactly one atom per subject and it came from
a worse model. `universe_builder retire --model gpt-4o-mini` moves them to `_retired/`,
which leaves each topic with no atom — precisely what `topics.needing_create`
looks for — so the next create run fills the gap. A move, never an unlink.

**The index atom is never retired, and that rule is why this is a command rather
than a one-line `find`.** Retiring a `history` atom does not schedule a
regeneration; it removes topics from the work list. A civilisation can keep one
atom per model by design, and an older model's atom can list many topics the
newer one does not. Retire it and those atoms become *orphans* — still on
disk, listed by nothing, absent from coverage and from `links.json` memberships,
invisible to every future pass. Much of a civilisation would stop existing
while the bytes sat there looking fine. A wrong split costs a duplicate someone
can see; this would cost an invisible hole.

Matching is a substring of the filename's *model segment*, parsed by `AtomName`
rather than scanned across the whole name, so a city named after a model is not
retired by accident.
