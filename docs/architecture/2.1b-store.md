### 2.1b Storage layer — `src/universe_builder/store.py`

The only module that turns an atom into a path, and a path back. It owns the
filename convention, the directory layout, the `_ERROR` sentinel and every write.

Before it existed, five modules each knew part of the layout and none owned it:
`fileName` in `llm_classes` held the convention, `LLMCall.__init__` assembled the
response path, `execute_prompt.augment_and_save_prompt` sliced `_ERROR` on and
off filenames with string arithmetic, `providers/batch.py` kept its own copy for
batch output, and the merge helper (now `operations/merge.py`) walked the tree. Changing the
convention meant finding all five.

| Function | Purpose |
|---|---|
| `path_for(atom_type, id, subject, model)` | Where a newly generated atom belongs. Append variants resolve to their base type's folder. |
| `dir_for(atom_type)` / `folder_name` | The directory for an atom type. |
| `read` / `read_json` | Load a stored payload. `read_json` returns `None` rather than raising, because `_ERROR` files frequently are not JSON at all. |
| `write` / `write_atom` | Atomic write, creating parents. |
| `write_error` / `clear_error` / `has_error` / `error_path` / `target_of_error` / `is_error_path` | The `_ERROR` sentinel, in one place. All of them are idempotent with respect to the suffix. |
| `read_atom` / `atom_type_of` | Migrate-on-read. `read_atom` carries a stored payload to the current schema version; `read_json` deliberately stays the raw, unmigrated view, because the fix pass needs to see exactly what is on disk. |
| `write_bytes` | The same atomic write for a sidecar's binary files (a domain's downloaded images), so nothing outside this module opens a path for writing under the data dir. |
| `write_json` | Write a plain dict in the corpus format. Uses `ensure_ascii=False`, matching Pydantic — a bare `json.dumps` escapes non-ASCII and makes an otherwise untouched file diff. |
| `commit_fix(sentinel, model_or_text)` | Under the target lock, refuse an existing target; stamp a model, write the fix, then retire its sentinel. Legacy strings must already be validated. |
| `iter_atoms(atom_type=None, include_errors=False)` | Walk stored atoms. With `include_errors`, sentinels sort ahead of their targets — the order the fix pass wants. |
| `iter_payloads(atom_type=None)` | `(path, read_json(path))` per stored atom, skipping a file that vanishes between the listing and the read; lint's walks use it, and collisions guards its reads the same way (v0.2.0). |
| `usable_text(path, unreadable=None)` / `is_placeholder(path)` | The one test of "is there an atom here": the text, or None when unreadable (the caller is told why) or the `{"error": ...}` placeholder. `topics.has_real_atom` (which also wants non-empty JSON), `topics._is_placeholder` and `work`'s selection read through it (v0.2.0; three copies before). |
| `is_empty_model(text_or_dict)` / `get_empty_model()` | The `{"error": ...}` `EmptyModel` placeholder: recognise one (strict, so a stamped sentinel is not one) and build one. Moved here from `functions.pydantic_helper` in v0.3.0. |
| `atom_id` / `normalise_topic` | The content-addressed id: BLAKE2b over `(base atom type, normalised topic)`, 16 hex characters prefixed `h`. Same topic, same id, every run. |
| `AtomName` | The naming convention, as a codec: it composes whatever id it is given and derives one only when given `None`, so a legacy name round-trips byte for byte. (`llm_classes/file_names.fileName`, an alias for it, went in v0.3.0.) |

**Ids are content-addressed.** `store.atom_id` hashes `(base atom type,
normalised topic)` with BLAKE2b to 16 hex characters, written with an `h` prefix.
The old form was `LLMCall.sequential_id`, a class counter restarting at 1 every
process, so regenerating a topic produced a different filename each run and there
was no idempotence at all. The digest is 64 bits — a birthday collision
probability of ~2.7e-8 at a million atoms; 48 bits would have been ~1.8e-3, not
negligible for a corpus expected to reach six figures.

Old and new are distinguishable without guessing: a legacy id is exactly ten
decimal digits, a content id always begins `h`. One alternation,
`\d{10}|h[0-9a-f]{16}`, is the only place that is written down. Stored corpora were
migrated to content-addressed ids by a `universe_builder migrate` verb
(`store.rename_plan` / `apply_rename`); once none held a legacy name the verb, the rename machinery,
`legacy_path_for`, `is_legacy_id` and `merge_helper`'s slug-plus-model pairing
key were deleted in v0.3.0. `AtomName` still parses and
composes the ten-digit form, which tests use as a fixture name; nothing pairs or
renames on it.

Normalisation is NFKC, whitespace collapse, then casefold — deliberately *not*
punctuation stripping or transliteration. The slug already drops both, so
"St. Petersburg" and "St Petersburg" share a slug; but they are different prompts
producing different content, and an id that folded them would let one overwrite
the other. **The id may split what the slug joins; it must never join what the
prompt splits.**

The base atom type is used, so `city` and `append_city` for one subject share an
id — which is what `merge_helper` pairs on, and the only thing it pairs on: two
subjects that merely share a slug (`St. Petersburg` vs `St Petersburg` — the id
splits what the slug joins) never pair. The slug-and-model fallback for
legacy-named files went with the rest of the legacy-id support in v0.3.0;
a name without a content id pairs with nothing.

Two properties are load-bearing:

- **Writes are atomic.** Every write lands in a temporary file in the destination
  directory and is `os.replace`d into position, so an exception mid-write leaves
  the previous contents intact rather than a truncated file. The verify pass
  rewrites files that are already valid, which is where this matters most.
- **Only the store retires a sentinel.** `commit_fix` writes the corrected file
  before clearing the `_ERROR`, and the caller must confirm the fix validated
  first. See §4.

### 2.1b-i Wire aliases — `models/subatomic.py::WireModel`

Two stored field names are misspellings of "discoverer":
`Artifact.finderOrDiscoveror` and `Discovery.discoverorOrInventor`. The wire
format cannot change — the stored corpus uses those keys, and the JSON schema
sent to the model asks for them — but the Python attribute can. `WireModel` sets
`populate_by_name` and aliases the two fields, so Python reads
`finderOrDiscoverer` while the JSON keeps `finderOrDiscoveror`.

Pydantic is a range now (`pydantic>=2.11,<3`, verified on 2.11.0 and 2.13.5),
floored at 2.11 because that is where the `serialize_by_alias` config landed —
so `WireModel` just sets `ConfigDict(populate_by_name=True,
serialize_by_alias=True)` rather than overriding `model_dump`/`model_dump_json`.
Both dumps emit the alias by default, which matters because `operations/
expand.py` rebuilds an atom from `model_dump()` output. (It was pinned at 2.6.0
with the two overrides before.)

`tests/test_models.py::TestAliasesOnlyAppearOnWireModel` walks every registered
model and fails if one aliases a field without inheriting `WireModel`. That is
the trap: an alias on a plain `BaseModel` reads old files correctly and then
silently rewrites every one of them under the new key.
