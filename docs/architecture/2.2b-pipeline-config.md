### 2.2b Pipeline config and CLI — `pipeline.yaml`, `pipeline.py`, `cli.py`

Model choices are data, not code. `src/universe_builder/pipeline.yaml` holds them and
`pipeline.py` resolves them, highest precedence first:

1. `--model` on the command line
2. `atoms.<atom>.<phase>` — a per-atom override
3. `phases.<phase>` — the phase default
4. `defaults.model` — the global fallback

`resolve_model` returns the value **and its provenance**, because a bare model
name does not tell you which of those four layers chose it — which is exactly
what you want to know before starting a large run.

**Reasoning effort** (v0.6.0, `providers/effort.py`) resolves the same way
(`resolve_effort`): `--effort`, then `effort.atoms.<atom>.<phase>`, then
`effort.phases.<phase>`, then `effort.default`, each validated on load. Unset
everywhere (the bundled file) sends nothing, so a run is byte for byte what it
was before. `run` takes `--effort` on every phase and path (sync, batch,
index), and so does `run_batch submit`; the dry run prints it beside the
model, a level the provider lacks (`max` on OpenAI) is refused before any
call (`effort.refusal`), and a run that sets one records it in `run.json`'s
config (only then, so an unset run's config hash is unchanged).
`OperationConfig.effort` → `_support.call_budget` → `ProviderCall(effort=)`
→ `build_request(effort=)` → `LLMRequest.effort` on the sync path;
`batch.submit(effort=)` on the batch path, which stamps the handle. A pack's
own verb that builds an `LLMRequest` passes `effort=` itself
(`effort.add_argument` gives it the same flag). `config.PHASE_MODELS` is
derived from this file rather than being a second copy to keep in step.

**Task budget** (v0.6.1, `providers/task_budget.py`) resolves the same way
again (`resolve_task_budget`, through the shared `_resolve_setting` and
`_setting_block`): `--task-budget N`, then `task_budget.atoms.<atom>.<phase>`,
then `task_budget.phases.<phase>`, then `task_budget.default`, each validated
on load (a whole number, at least 20,000). Unset everywhere (the bundled
file) sends nothing. `run` takes `--task-budget` on every phase and path
(sync, batch, index), and so does `run_batch submit`; the dry run prints it
beside the model and effort (`task budget N of max_tokens M (source)`, or
"none sent" for a provider that ignores it; nothing when unset); a budget
under the minimum is an argument error, and one over the phase's `max_tokens`
or for a Claude model without the capability is refused before any call
(`task_budget.refusal`). `run.json`'s config gets `task_budget` (the sent
value) only when one is sent. The carriers mirror effort's:
`OperationConfig.task_budget` → `_support.call_budget` →
`ProviderCall(task_budget=)` → `build_request(task_budget=)` →
`LLMRequest.task_budget`; `batch.submit(task_budget=)`, which stamps the
handle. `run --experiment` with a budget set (flag or config) is refused,
since B would run without it; `experiment replay` sends none on either arm.
