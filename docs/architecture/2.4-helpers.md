### 2.4 Helpers — dissolved into `store`, `index` and `operations/` (v0.3.0)

`functions/` held three helper modules; v0.3.0 moved each to the
module that owns its subject. The old modules re-exported the new homes for
one release; v0.4.0 deleted them, so `universe_builder.functions` no longer
imports.

| Was | Now | Purpose |
|---|---|---|
| `functions.json_helper` | `index.load_atom_from_json(path, cls)` | Read a file straight into an atom instance. `topics` imports it lazily (`index` imports `topics`). |
| `functions.pydantic_helper` | `store.get_empty_model()` / `store.is_empty_model()` | The failure sentinel. The unused recursive coercion helper had already been removed. |
| `functions.merge_helper` | `operations/merge.py` | `process_directory()` pairs `city_*.json` with its `append_city_*.json` (on the content id alone; v0.3.0 dropped the slug+model key for legacy names) and promotes the merged, *validated* payload over the city file in place; the consumed append retires to `_merged/`. Lists extend idempotently, the base wins every scalar conflict. The walk prunes underscore-prefixed (machinery) folders, so a pair kept in `_backups/`, `_merged/` or `_retired/` is never merged (v0.1.20). |
