### 2.1g Prompt experiments — `src/universe_builder/experiments.py`, `prompt_spec.py`, `experiment_stats.py` (v0.5.0)

A prompt experiment compares a candidate prompt (B) with the live one (A) on
the same subjects, pairwise.

```
run --phase create --batch --experiment NAME        shadow: A is the real batch, unchanged;
                                                    B runs on a hashed sample of the same subjects
experiment replay NAME --variant V --apply          replay: A and B both regenerated for subjects
                                                    that already have atoms
experiment collect NAME                             B (and replay's A) from the experiment's own handles;
                                                    shadow's A copied read-only from the corpus journal
experiment judge NAME [--model M] [--effort E] [--sample N] --apply
                                                    blind pairwise judge, both orders (paid); each
                                                    (model, effort) is its own judge
experiment report NAME [--judge-model J] [--panel J1,J2]
                                                    pairs, guardrails, judge tally, the verdict,
                                                    cost per arm and per judge (free)

v0.6.0, model and effort as the variable:
experiment replay NAME [--variant V] --model-b MODEL_OR_TIER [--effort-a E] [--effort-b E]
                  [--allow-dear-b] [--reuse-a FROM] --apply
run --phase create --batch --experiment NAME --model-b M [--effort-b E] [--allow-dear-b]
```

**Test data never meets the corpus.** Everything an experiment writes is
under `settings.experiments_dir()` (`<base>/experiments/<domain>`, the sibling
of the data base; `UNIVERSE_BUILDER_EXPERIMENTS_DIR` overrides it, and a root
that overlaps the data directory is refused). `store.write_experiment` and
`store.append_experiment_line` are its only writers and refuse any path
outside that root. `store.write_atom` and `store.write_error` refuse any path
inside it. Experiment handles are wrapped (`HANDLE_MARK`), so
`providers.batch.load` refuses them and `collect --all` cannot find them. No
experiment call is journalled into the corpus journal, so index provenance,
the fix queue and `costs` never count one. The experiment folder keeps its
own spend.

**What an arm sends.** A `PromptSpec` holds the persona, the operation texts,
the per-type examples and prompt starts, and the neighbours/notes toggles.
`PromptSpec("live")` and `"aa"` (the A/A control) are the pack as it stands.
A variant is `<pack.variants_dir>/<name>/variant.yaml` plus files beside it,
loaded strictly (an unknown key, atom type or file is an error).
`build_request(prompt=spec)` reads a spec fresh rather than through the
module caches, which are keyed on nothing a spec changes. `prompt=None`, the
only value the pipeline passes, is byte-for-byte unchanged
(`test_experiments.py` pins live against `build_requests`).
`PromptSpec.fingerprint` hashes what is sent (probe requests plus toggles,
not the notes file's contents, which grow each line). An experiment
reattaches only while both arms' fingerprints, its mode, its variant and its
acceptance thresholds are unchanged, and pairs pool only then.

**Reference candidates** (v0.5.5): a variant with `create_candidates: true`
offers the subject's `DomainPack.create_candidates` in the create prompt's
user turn: at most 3, each a title, one sentence (40 words at most) and a URL.
They're introduced as possibly about a namesake, to use only if clearly this
entry and to cite if used. Off in the live prompt. `experiment replay --only
IDS_FILE` samples just the named atoms (e.g. the obscure ones).
v0.5.8 adds three pieces:
- `DomainPack.create_candidates_live` turns the same block on for the
  pipeline's own create (`topics.create_instructions`, through the one
  builder, `prompt_spec.candidates_block`), once a candidates variant has won.
- `create_candidates_version` enters the fingerprint whenever candidates are
  on, so a changed hook never pools with the old one.
- `experiment_report_only_checks` are reported but left out of the
  check-flags guardrail. Reports also count `judged.no_reference`: complete
  pairs the judge never saw because no reference resolved.

**Cheap models only.** Each atom type's resolved model must output at or
under `pipeline.yaml`'s `experiments.max_output_price` (USD per 1M tokens;
1.0). The check is on price, not tier name, and is refused before A is
submitted. B uses A's model and A's effort unless told otherwise, so by
default the variable is the prompt.

**Model and effort as the variable** (v0.6.0). `--model-b` (a model id or a
tier) runs B on another model, `--effort-a`/`--effort-b` set each arm's
reasoning effort (`providers.effort`; B's defaults to A's). The ceiling holds
A always and B unless `--allow-dear-b`. B's batches go to the provider its
model id names (`pricing.provider_for`), so A on OpenAI and B on Anthropic is
one experiment with separate batches per provider; each wrapped handle
records its arm's `model` and the effort it **sent** (`effort.sent`: none
for a model or provider that takes none, so `--effort-b low` on gpt-4o-mini
records nothing), which is also stamped on the handle (`extra["effort"]`) and
copied to each reply. Whether the arms differ is decided on **resolved**
values (`experiments.arm_resolution`, `resolutions_differ`): per atom type,
the model and the effort sent. `--model-b` naming A's own model (or a tier
that resolves to it), or `--effort-b` equal to A's, is no difference. With B
differing, the variant may send the live prompt: `--variant` defaults to
`live`, and a variant with no overrides (one that only carries `acceptance`,
like the pack's planned `aa-sol`) is accepted; without a difference both are
refused as before. `meta.arms.<arm>.resolved` (`{atom: {model, effort}}`) is
recorded for both arms at prepare and submit (also for an arm not submitted
there: shadow's A, a reused A), with `model`/`effort` summaries (one value,
or per atom) and (A) `reused_from`; a run that would change any of them is
refused (`prepare`, `submit`), so a model or effort change is a new
experiment. The `aa_check` applies only when the arms do not differ.
`--reuse-a FROM` copies FROM's sample (weights and all) and its collected A
replies (`experiments.reuse_a`, each marked `reused_from`) and submits B
only, for the subjects FROM has an A for. **The reused A must be today's A**:
FROM's A prompt fingerprint must be today's live one, FROM must record its
A resolution (a pre-v0.6.0 experiment does not, and is refused rather than
guessed from today's `pipeline.yaml`), and every reply's `prompt_sha256`
(recorded at submit by `build_arm_requests`, `prompt_digest`: system text,
examples, user turn with its note, neighbours and candidates, schema and
`max_tokens`) must equal the digest of what today's A would send for that
subject; any mismatch, or a reply with no digest (pre-v0.6.0, or a shadow A
copied from the corpus journal), refuses the reuse. Only atom types FROM
sampled and today generates are taken. It cannot be combined with
`--effort-a`, `--only` or `--context`. Several B arms then compare with one
byte-identical A. Shadow mode takes `--model-b`/`--effort-b`/`--allow-dear-b`
too (`run` refuses them without `--experiment`); its A is the real create
batch at the run's own `--effort`, and `pull_corpus_a` copies the effort that
batch sent from the journal.

**Sample.** For each atom type, the top `max(min_per_type, ceil(rate·N))`
subjects ranked by blake2b(experiment, atom, content id). The sample is
deterministic and independent of list order. Each subject carries an
inverse-probability weight. Subjects with a result or an in-flight request
for an arm are skipped.

**Judged on.**
- Free, generic: validity at first try (each arm's raw reply through the
  same `model_validate_json`), fill %, uncached-equivalent cost and output
  tokens.
- Free, the pack's: `DomainPack.experiment_checks(atom, subject, context,
  payload) -> {check: flags}`.
- Paid: a judge reads both arms against
  `DomainPack.experiment_reference(atom, subject, context)`. The reference is
  chosen from the listed name, never from either arm's citations, and frozen
  on first use. The judge lists per record `wrong_subject`, `contradictions`,
  `false_certainty` and `coverage` (`PairAssessment`). The code picks the
  winner lexicographically. A side wins a pair only by winning both orders.
  If the judge calls both records the wrong subject in either order, the
  pair is set aside as a reference miss, because the reference is the wrong
  article, and it is counted rather than tied (v0.5.1).
  `DomainPack.experiment_rubric` is prepended to the engine's instructions.
  A judge is a (model, effort) pair (v0.6.0): each line carries
  `judge_model` and, when one was set, `judge_effort`, read back as one label
  (`judge_label`: `model` or `model@effort`; lines from before are their
  model). `plan_judging` skips only what this judge has judged, so a second
  judge's verdicts sit beside the first's. On Anthropic the reply goes
  through the provider's structured-output path (`output_config.format` with
  `PairAssessment`), the effort beside it. `report --panel J1,J2`
  (`experiments.panel`) gives each judge's tally, the agreement rate over the
  pairs every judge judged in both orders (and over pairs any judge found
  decisive), and a verdict drawn on the agreed pairs only: a pair counts when
  every judge gives it the same outcome. A judge named twice, or one with no
  judgements on the experiment (a typo, a wrong `@effort`), is refused;
  `report --config` resolves a judge's tier.
- Cost: each reply is priced at collect on its own model's row at batch rates
  (`estimate_cost(..., handle.model, batch=True)`), each judgement on its
  judge's row at sync rates. `report` sums `spend` per arm (`A`, `B`, and
  `A_reused`, paid in the experiment it came from) and per judge
  (`spend.judges`), and lists the models and efforts each arm's replies came
  back from (`arms`).

**Verdict** (`experiments.verdict`, arithmetic in `experiment_stats`):
- **REJECT** at any look, on a failed guardrail or on B significantly worse
  (one-sided sign test, P < 0.01). The guardrails are validity (a
  discordant-count margin), fill and check flags (sign-flip permutation test
  plus a margin), and cost (a ratio cap).
- **ADOPT** only at the pre-registered `target_decisive` (120), on a
  one-sided exact sign test, P < 0.05.
- **ADOPT IF CHEAPER**, at target, for a non-inferior B (a one-sided 95%
  lower bound on the tie-inclusive score ≥ 0.45) that is ≥ 10% cheaper.
- **NO DIFFERENCE** at target otherwise. **CONTINUE** below target.

**A model or effort A/B is judged on quality** (v0.6.0, `verdict(model_ab=)`,
`report`'s `model_ab` when `arms_differ`). A dearer model is the point of the
question, so the cost guardrail does not gate it: the verdict is **B BETTER**
(the sign test as for ADOPT), **A BETTER** (B significantly worse), **NO
DIFFERENCE** at target, **CONTINUE** below it, or **REJECT** on a failed
validity, fill or flags guardrail, with the cost ratio beside it
(`cost_ratio`; rendered `B BETTER, 3.0x cost`, the cost row "reported
only"). A variant that sets `cost_cap` itself (`meta.acceptance_set`) gates
on it as before. A prompt experiment (arms on one model and effort) is
judged exactly as before.

An `aa` run must come out CONTINUE or NO DIFFERENCE. Nothing is ever applied:
a person promotes a variant by a commit to the pack.
