### 2.1f-v Period consistency — `src/universe_builder/domains/history/periods.py`, `universe_builder periods`

This whole subsystem is **history-specific and lives in the history domain**,
not in core: it is registered as the history pack's `periods` operation
(`registry.py`, `DomainPack.operations`, an `OperationSpec` carrying the
handler, the help line and the verb's own flags), and `cli.py` builds one
subparser per declared operation and dispatches to its handler — a domain
that declares none (medications) simply has no `universe_builder periods` verb. Core
knows no operation by name: before, `cli.py` built the
`periods` subparser itself, with its flags, and a second domain verb was an
argparse error. `cli.cmd_operation(name, args)` is the by-name dispatcher
for a caller with a namespace in hand (`cmd_periods` remains as its alias).
So core carries no regime/government/period logic.

Uniformity by construction, after the 25-city repair proved a schema
description is a *soft* instruction: most cities split their over-broad
periods, Alexandria's survived, because a whole-file verify acts on a rule
only when the model notices it, once per city. The decision is therefore
taken away from the model:

- **The regime table** (`domains/history/regime_changes.txt`) is aliases.txt's
  sibling: a small human-curated reference of *enum-level* government changes
  per civilisation (`1953: monarchy -> modern republic`), applied to the
  cities that civilisation's History lists (resolved through
  `topics.subject_resolver`, so the lint and the work list cannot disagree
  about which atom a name is). A dynasty change that keeps the enum value is
  deliberately not a line — it would demand splits that change nothing.
- **`lint()`** flags every period whose span strictly contains a table date,
  and every period signature whose `typeOfGovernment` disagrees across
  cities. Deterministic, read-only; `universe_builder periods` exits non-zero while
  anything is flagged, so a script can gate on a clean corpus.
- **`adjudicate()`** settles disagreements by majority, *mechanically*: the
  minority files get the winning value by data edit — validated as
  `CityExpanded`, written through `store`, journaled as an adjudication with
  no payload because no model was involved. One answer exists per signature,
  so drift is impossible. Ties are reported, never guessed.
- **`split_flagged()`** sends each flagged period out as one `PeriodSplit`
  call (a wrapper model whose `periods` list replaces the original — expand's
  single-`Population` shape cannot split, which is why the micro-operation
  exists) and splices the reply in mechanically. A failed reply leaves the
  period in place and flagged. Convergence is the re-run of `lint()` finding
  nothing: a machine verdict, not a model's mood, and the loop resumes from
  wherever it was killed because the checker only ever flags what remains.
